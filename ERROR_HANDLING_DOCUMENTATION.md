# Документация по обработке ошибок в RTO сервере

## Обзор улучшений

В серверную часть RTO системы была добавлена комплексная обработка ошибок и валидация данных для повышения надежности и диагностики проблем.

## Основные улучшения

### 1. Валидация при создании сессии (`StartOptimizeSession`)

#### Проверки базовых параметров:
- **Метод оптимизации**: Проверка на существование и поддержку метода
- **Количество итераций**: Диапазон от 1 до 10000
- **Наличие переменных**: Проверка существования MV и CV
- **Лимиты количества**: Максимум 50 MV и 100 CV

#### Валидация управляемых переменных (MV):
- **ID и имя**: Проверка на пустоту и длину (максимум 100/200 символов)
- **Тип данных**: Поддержка "Numeric", "Boolean", "Integer"
- **Границы**: Корректность нижней и верхней границ
- **Специальные значения**: Проверка на NaN и бесконечности

#### Валидация контролируемых переменных (CV):
- Аналогичные проверки как для MV
- Проверка корректности ограничений

### 2. Обработка ошибок в итерациях (`OptimizeIteration`)

#### Валидация запроса:
- **ID сессии**: Проверка на существование
- **Статус сессии**: Проверка на ошибочные состояния
- **Данные CV**: Валидация полученных значений

#### Проверки значений CV:
- **Тип данных**: Числовые значения
- **Корректность**: Проверка на NaN и Inf
- **Количество**: Соответствие ожидаемому количеству
- **Разумность**: Проверка на подозрительно большие значения (> 1e15)

#### Валидация MV перед отправкой:
- **Количество**: Соответствие конфигурации
- **Тип и корректность**: Числовые значения без NaN/Inf
- **Границы**: Автоматическое ограничение в пределах границ

### 3. Улучшенная обработка ошибок в `external_model`

#### Дополнительные проверки:
- **Валидация входных MV**: Размерность и корректность значений
- **Обработка timeout**: 30-секундный лимит ожидания CV
- **Проверка данных от клиента**: Валидация полученных CV
- **Обработка исключений**: Try-catch с детальным логированием

### 4. Мониторинг и статистика сессий

#### Фоновый мониторинг:
- **Автоматическая очистка**: Удаление неактивных сессий (>2 часов)
- **Статистика**: Подсчет созданных, завершенных и ошибочных сессий
- **Логирование**: Регулярные отчеты о состоянии системы

#### Расширенный статус сервиса:
- **Время работы**: Отслеживание uptime
- **Детальная статистика**: Количество сессий по статусам
- **Динамический статус**: "active", "idle", "degraded"

### 5. Улучшенные методы управления сессиями

#### Приостановка (`Pause`):
- **Валидация ID**: Проверка существования сессии
- **Проверка статуса**: Предотвращение некорректных операций
- **Информативные сообщения**: Детальные ответы о состоянии

#### Остановка (`Stop`):
- **Безопасная остановка**: Корректное завершение потоков
- **Timeout обработка**: Ограничение времени ожидания завершения
- **Очистка ресурсов**: Удаление файлов сессии

## Типы ошибок и их обработка

### Критические ошибки (flag=4):
- Отсутствие сессии
- Некорректные данные от клиента
- Ошибки валидации
- Проблемы с обработкой итераций

### Предупреждения (WARNING):
- Значения MV вне границ (с автокоррекцией)
- Зацикливание в оптимизации
- Подозрительно большие значения

### Информационные сообщения (INFO):
- Успешное создание сессий
- Прогресс оптимизации
- Статистика системы

## Логирование

### Структура сообщений:
```
[SERVER][УРОВЕНЬ] Сообщение
```

### Уровни логирования:
- **CRITICAL**: Критические ошибки системы
- **ERROR**: Ошибки в обработке запросов
- **WARNING**: Предупреждения о потенциальных проблемах
- **INFO**: Информационные сообщения
- **DEBUG**: Отладочная информация

## Файлы сессий

### Автоматическое создание:
- JSON файлы с историей итераций
- Метаданные сессии
- Автоматическая очистка при завершении

### Содержимое:
```json
{
  "session_id": "uuid",
  "start_time": "ISO datetime",
  "optimization_method": "method_name",
  "MVs": [...],
  "CVs": [...],
  "iterations": [...]
}
```

## Рекомендации по использованию

### Для разработчиков клиентов:
1. Всегда проверяйте поле `is_good` в ответах
2. Обрабатывайте сообщения об ошибках
3. Следите за корректностью отправляемых данных
4. Учитывайте timeout'ы (30 секунд для итераций)

### Для администраторов:
1. Мониторьте логи сервера
2. Настройте ротацию логов
3. Следите за статистикой сессий через `GetServiceStatus`
4. Регулярно проверяйте файлы сессий

## Коды возврата

### Флаги в OptimizeIterationResponse:
- **0**: Успешная итерация
- **3**: Оптимизация завершена
- **4**: Ошибка
- **-1**: Критическая ошибка (устаревший)

### Поля в StartResponse:
- **is_good**: `true` при успешном создании сессии
- **message**: Описательное сообщение
- **optimization_instance_id**: ID созданной сессии

## Примеры сообщений об ошибках

### Валидация MV:
```
Ошибки в MV[0]: ID не может быть пустым; Нижняя граница (10.0) должна быть меньше верхней (5.0)
```

### Ошибки итерации:
```
Некорректное количество MV: получено 5, ожидалось 6
```

### Проблемы с CV:
```
CV[2] не может быть NaN
```

Эта система обработки ошибок значительно повышает надежность RTO сервера и упрощает диагностику проблем.
